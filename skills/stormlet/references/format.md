# The .stormlet format

A `.stormlet` file is UTF-8 JSON, at most 20 MB. This page covers version 13, the version to write. Stormlet reads every version from 1 to 13. It refuses files from a newer version, and files with an invalid field.

```json
{
  "format": "stormlet",
  "version": 13,
  "layout": "flow",
  "title": "Board title",
  "frames": [],
  "stickies": [],
  "connections": []
}
```

| Field         | Required | Notes                                                                                                                                                      |
| ------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `format`      | yes      | Always `"stormlet"`                                                                                                                                        |
| `version`     | yes      | `13`                                                                                                                                                       |
| `title`       | no       | The board name and the download file name. Single line.                                                                                                    |
| `layout`      | no       | Draft only. How the board arranges its frames and loose notes: `grid`, `column`, `row`, `flow` or `flow-down`. Leave it out for the default row of frames. |
| `stickies`    | yes      | Notes, text boxes and drawings, from bottom to top. May be empty.                                                                                          |
| `frames`      | no       | Frames that group notes                                                                                                                                    |
| `connections` | no       | Lines between notes and frames                                                                                                                             |

## Drafts and saved files

From version 12, positions, sizes and most style fields are optional. A file that leaves them out is a **draft**: Stormlet lays it out when the file is opened, and then saves it with every field filled in. A file Stormlet saved therefore always has `x`, `y`, `z`, `width` and `height` on every object. Both forms are valid; when you write a new board, write a draft.

## Frames: `frames[]`

| Field             | Default in a draft | Values                                                                                                                                                                                                 |
| ----------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`              | required           | Unique among frames                                                                                                                                                                                    |
| `title`           | `"Frame"`          | 1–100 characters. Shown above the frame.                                                                                                                                                               |
| `layout`          | `"grid"`           | How the frame arranges the notes and frames placed into it: `grid`, `column`, `row`, `flow` or `flow-down`. Draft only.                                                                                |
| `frame`           | none               | The `id` of the frame this frame sits in. Draft only, and ignored when the frame has a position. A missing frame, or a chain of frames that leads back to itself, puts the frame on the board instead. |
| `color`           | `"none"`           | `none`, `gray`, `blue`, `green`, `yellow`, `pink`, `purple`                                                                                                                                            |
| `borderWidth`     | `2`                | 1, 2, 3, 4, 6 or 8                                                                                                                                                                                     |
| `x`, `y`          | laid out           | The top-left corner. A frame with a position keeps it.                                                                                                                                                 |
| `width`, `height` | fits its notes     | 160–20000 wide and 120–20000 tall. A frame grows to fit the notes placed into it.                                                                                                                      |
| `locked`          | `false`            | A locked frame cannot be moved, but its notes stay editable                                                                                                                                            |

A note belongs to a frame when the frame's rectangle fully contains the note's rectangle. Membership is not stored. A frame may sit inside a larger frame.

## Lines: `connections[]`

| Field                    | Default in a draft    | Values                                             |
| ------------------------ | --------------------- | -------------------------------------------------- |
| `id`                     | `line-1`, `line-2`, … | Unique among lines                                 |
| `from`, `to`             | required              | An end, as described below                         |
| `label`                  | `""`                  | Up to 300 characters, shown on the line            |
| `path`                   | `"elbow"`             | `elbow`, `straight`, `curve`                       |
| `color`                  | `"slate"`             | `slate`, `black`, `blue`, `red`, `green`, `purple` |
| `width`                  | `2`                   | 1, 2, 3, 4 or 6                                    |
| `dashed`                 | `false`               |                                                    |
| `startArrow`, `endArrow` | `false`, `true`       |                                                    |
| `locked`                 | `false`               |                                                    |

Each end is written in one of these forms:

- `"k1"`: in a draft, the `id` of a note, or of a frame when no note has that `id`. The line attaches to the side nearest the other end.
- `{ "stickyId": "k1", "side": "right" }` or `{ "frameId": "keep", "side": "auto" }`: `side` is `auto`, `top`, `right`, `bottom` or `left`. It may be left out in a draft, and then it is `auto`.
- `{ "x": 100, "y": 40 }`: a free end at a board position.

A line whose note or frame does not exist is left out. The rest of the board still opens.

## Layout of a draft

When a file is opened, Stormlet places the objects that have no position:

1. It starts at the top left, or below the objects that do have a position.
2. Loose text boxes are stacked first, as headings.
3. Every frame arranges what is placed into it (its notes, then the frames inside it) by its `layout`, with 40 px padding, and grows to fit. Inner frames are measured first, so a frame's size follows from its contents.
   - `grid`, `column` and `row` use uniform cells as large as the largest object, 24 px apart.
   - `flow` puts each object one column to the right of the objects whose lines point to it, 120 px apart. The objects of a column are 48 px apart and centred on the tallest column. A line between objects in different frames counts between the frames that hold them, where those frames meet. A line that would close a cycle is ignored.
   - `flow-down` is the same, top to bottom: one row per step, 120 px apart.
4. Without a board `layout`, frames follow in one row, in file order, 80 px apart, and frames that give no height share the height of the tallest. Loose notes go in a grid below the row. With a board `layout`, the board arranges its loose notes and frames the way a frame would.
5. Notes keep their file order. Unordered notes are stacked above the highest given `z`.

The same file always opens the same way.

## Placement when a board is edited

When a file mixes objects with positions and objects without, the ones without are placed around the others:

- A note placed into a positioned frame goes below the objects that frame already holds, and the frame grows to fit.
- A loose note joined by a line to a positioned note or frame goes into the nearest free spot beside it: 80 px after it when the line comes from it, before it when the line goes to it. It stays out of every frame.
- Other objects go below everything that has a position.

## Lines

Stormlet draws an elbow line around the notes in its way. When several lines leave one side of an object, they are spread along that side in the order of their other ends. An `auto` end avoids a side that another note crowds, so it is rarely worth fixing `side` by hand.

## Readable draft layouts

The board and each frame accept optional `spacing` with numeric fields `gap`, `rankGap`,
`crossGap`, and `padding` (0–2000 px, finite numbers). Board values are inherited by all
frames; a frame overrides individual fields. Defaults remain 24, 120, 48, and 40 px.
The default board row uses 80 px between frames unless `gap` is supplied.

A root frame with `"role": "legend"` is placed after loose headings and before the main
flow. Multiple legends stack in file order. Nested frames do not become board legends.
Use `"layout": "row"` and a separate colored sticky for each notation role. Positioned
frames retain their coordinates, including positioned legends. These hints are consumed
on import; saved files keep the resulting geometry rather than the layout settings.

Example draft settings:

```json
{
  "layout": "flow",
  "spacing": { "gap": 80, "rankGap": 180, "crossGap": 100, "padding": 60 }
}
```

Spacing and legend hints are optional version-13 extensions. Older builds may ignore
these hints; use explicit positions when distributing to an older build.
