# ADR 0009: 진단 로그와 복구

- 상태: 채택
- 날짜: 2026-11-08
- 선행: [로컬 우선 계층 구조](0001-layered-local-first.md)

## 배경

Stormlet은 서버 없이 사용자의 브라우저에서만 돈다. 문제가 생겨도 개발자가 볼 수 있는 로그가 없고, 예외를 삼키는 곳(브라우저 저장소, 클립보드, 파일 열기)은 흔적을 남기지 않았다. 그중 둘은 데이터 손실로 이어졌다. 저장된 보드를 읽지 못하면 빈 보드로 시작해 첫 저장에서 원본을 덮어썼고, 저장 공간이 가득 차면 "자동 저장" 표시가 그대로인 채 저장이 조용히 실패했다. 화면을 그리다 오류가 나면 흰 화면만 남았다.

## 결정

1. **메모리 안의 진단 로그**: `src/adapters/diagnostics/log.ts`가 `debug`·`info`·`warn`·`error` 단계의 기록을 최근 200개까지 메모리에 둔다. 기록은 `store.save-failed`처럼 점으로 나눈 고정 이벤트 이름과 작은 세부값(오류 이름·메시지·스택 상단, 키, 개수)이다. 포스트잇 내용은 남기지 않는다. 테스트 밖에서는 같은 기록을 `[stormlet]` 접두어로 콘솔에도 쓰고, `debug`는 개발 빌드에서만 남긴다. 어디서든 부를 수 있도록 모듈 단위 싱글턴으로 둔다.
2. **원격 수집 없음**: 로그는 사용자가 복사할 때만 브라우저를 떠난다. 서버가 없고 보드를 외부로 보내지 않는 원칙(ADR 0001)과 맞추기 위해서다. 필요해지면 같은 로그에 선택형 출력 대상을 붙인다.
3. **기록 지점**: 예외를 삼키던 곳은 모두 기록한다. 처리되지 않은 오류와 거부된 프로미스는 `main.tsx`에서 전역으로 받는다. 시작 시 버전과 보드 크기도 남긴다.
4. **복구 화면**: 보드를 그리다 오류가 나면 `AppErrorBoundary`가 흰 화면 대신 복구 화면을 보여 준다. 저장소에는 오류 전까지의 편집이 남아 있으므로 보드를 내려받을 수 있고, 다시 시도하면 저장소에서 보드를 다시 그린다.
5. **읽을 수 없는 저장본 보관**: `LocalBoardStore`는 읽지 못한 저장본(손상, 또는 더 새로운 버전의 포맷)을 `stormlet.board.damaged`로 복사해 둔 뒤 빈 보드로 시작하고, 원본을 앱에 넘긴다. 앱은 시작하자마자 원본을 내려받을 수 있는 대화상자를 띄운다. 복사본은 자동으로 지우지 않는다.
6. **저장 실패 알림**: 브라우저가 저장을 거부하면 저장소가 `watchSaved`로 알리고, 제목 아래 "자동 저장" 표시가 경고로 바뀐다. 거부된 저장은 다음 편집이나 페이지를 숨길 때 다시 시도하고, 성공하면 경고가 사라진다. `watchSaved`는 `BoardStore`의 선택 메서드라 실패할 일이 없는 저장소는 구현하지 않아도 된다.
7. **진단 정보 복사**: 설정의 "문제 해결"과 복구 화면에서 버전, 브라우저, 언어, 보드 크기, `stormlet.*` 키별 저장 공간 사용량, 최근 로그를 텍스트로 복사한다. 클립보드를 쓸 수 없으면 직접 복사할 수 있게 텍스트를 보여 준다. 이슈 템플릿이 이 내용을 받는다.
8. **규칙으로 강제**: 아키텍처 테스트가 진단 로그 파일 밖의 `console` 사용을 실패시킨다. 모든 메시지가 로그를 거쳐야 버그 리포트에 실린다.

## 결과

- 사용자가 겪은 문제를 진단 정보 한 덩어리로 재현 단서와 함께 받을 수 있다.
- 로그는 새로고침하면 사라진다. 오류 화면이나 같은 세션에서 복사해야 한다.
- 손상된 저장본 복사본은 저장 공간을 차지한다. 진단 정보의 저장 공간 사용량에 드러나므로 용량 문제가 생기면 그것부터 본다. 원본만큼 공간이 남지 않아 복사에 실패하면 이를 기록하고, 원본은 대화상자에서 내려받을 수 있다.
- 오류 메시지 자체에 데이터가 섞이는 것까지 막을 수는 없으므로, 로그에 넘기는 세부값은 리뷰에서 본다.
