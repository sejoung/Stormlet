# ADR 0010: Google Drive 동기화

- 상태: 채택, 실제 OAuth 환경 검증 대기
- 날짜: 2026-11-08
- 선행: [협업으로 옮길 수 있는 보드 모델](0002-collaboration-ready-model.md), [진단 로그와 복구](0009-diagnostics.md)

## 배경

보드는 브라우저 저장소와 내려받은 파일에만 있었다. 여러 기기에서 쓰거나 백업하려면 사용자가 직접 파일을 옮겨야 했다. 서버 없이 정적 호스팅을 유지하면서 사용자의 Google Drive를 저장소로 쓰려 한다. 첫 범위는 연결, 폴더에 저장, 열기, 자동 저장, 다른 곳의 변경 병합, 새로고침 후 재연결이다. 탭 간 토큰 공유와 만료 전 연장은 뒤로 미룬다.

## 결정

1. **선택 기능**: 공개 설정 세 개(Client ID, API 키, App ID)가 빌드에 있을 때만 켠다([설정 안내](../google-drive.md)). 없으면 Drive 코드는 만들어지지 않는다.
2. **`drive.file` 범위와 메모리 토큰**: 앱이 만들었거나 사용자가 Picker로 고른 파일에만 접근한다. 토큰은 메모리에만 두고 어디에도 저장하지 않는다. 로그인 팝업은 사용자 동작 안에서만 열 수 있어, Google 스크립트는 대화상자를 열 때나 기억한 파일이 있을 때 미리 불러온다.
   - **탭 간 공유**: 같은 origin의 열린 탭끼리 `BroadcastChannel`로 토큰을 넘긴다. 새 탭은 `request`를 보내고, 연결된 탭은 절대 시각이 아니라 남은 수명을 보낸다. 받는 탭은 지금 가진 것보다 늦게 끝나는 토큰만 받는다. 연결 해제는 모든 탭에 적용하고 권한 철회는 해제한 탭에서 한 번만 한다(결정 13). Drive가 401로 거부한 토큰은 그 토큰을 가진 탭에서만 지운다. 메시지는 형식을 검증한 뒤 처리하고, 채널이 없는 브라우저는 탭마다 직접 연결한다. 쿠키·sessionStorage는 XSS에 똑같이 노출되고 정적 배포에서 `HttpOnly`를 쓸 수 없어 채택하지 않았다.
   - **만료 전 연장**: refresh token이 없으므로 만료 10분 전부터 `연장` 상태를 보이고, 그동안 앱을 클릭하면 `prompt: ''`로 토큰을 다시 받는다. 타이머로 팝업을 열면 브라우저가 차단하고, 키 입력은 팝업이 포커스를 가져가 타이핑을 끊으므로 클릭만 쓴다. 실패하면 그 토큰이 끝날 때까지 클릭 연장을 멈추고 버튼으로만 연장한다. 만료되면 즉시 동기화를 멈추고 `다시 연결`을 표시한다.
3. **저장소를 감싸는 동기화**: `DriveSync`(application)는 `BoardStore`를 구현해 로컬 저장소를 감싼다. 편집은 곧바로 로컬에 쓰고, 연결된 파일에는 2초 멈춤(최대 10초) 뒤 쓴다. 다른 곳의 변경은 다른 탭의 변경처럼 외부 패치로 편집기에 들어가므로 실행 취소 기록에 섞이지 않는다. 화면·세션은 바뀌지 않는다(ADR 0002).
4. **포트와 어댑터**: 도메인은 `RemoteBoards`(열기·버전·저장·만들기)와 `RemoteLinks`(연결 기억)만 안다. 파일 형식, 파일 이름(보드 이름), HTTP 상태와 실패 사유의 대응은 `adapters/drive`가 맡는다. 실패는 `auth`·`conflict`·`permission`·`full`·`missing`·`network`·`unreadable`로 나뉜다. 403은 Google의 오류 사유로 나눠, 요청 한도 초과는 `network`(다시 시도), 저장 공간 부족은 `full`로 본다.
5. **버전 확인과 3방향 병합**: 저장 직전에 파일 버전을 읽어 기억한 버전과 비교하고, ETag가 있으면 `If-Match`도 보낸다. 다르면 파일을 읽어 마지막 동기화 보드 / 현재 보드 / 원격 보드를 기록과 필드 단위로 병합한다(`domain/sync/merge.ts`). 위치(x, y)와 크기(width, height)는 한 값으로 다룬다. 같은 필드를 다르게 바꾼 경우와 삭제·수정 경합만 충돌이다. 병합 뒤 끝점을 잃은 연결선은 버린다.
6. **충돌은 사용자가 고른다**: 충돌이 있으면 저장을 멈추고 항목마다 내 변경과 Drive 변경을 고르게 한다. 고르는 동안의 편집은 로컬에 남고, 고른 뒤 다시 병합해 저장한다.
7. **기준 보드를 기억**: 새로고침 뒤에도 병합할 수 있도록 연결한 파일의 ID·이름·버전과 마지막 동기화 보드를 localStorage에 둔다. 토큰은 두지 않는다. 둘은 함께 쓰거나 함께 지운다. 저장 공간이 차서 기준 보드를 쓰지 못하면 새 버전과 예전 기준 보드가 짝지어 남아 새로고침 뒤 잘못 병합하므로, 둘 다 지우고 연결은 페이지가 열려 있는 동안만 유지한다. 로컬 보드 저장본을 읽을 수 없으면 이 기준 보드에서 다시 시작한다. 빈 보드로 시작하면 병합이 그것을 '모두 삭제'로 읽고 Drive에 저장하기 때문이다.
8. **실패 처리**: 인증 만료는 `다시 연결` 상태로 멈춘다. 네트워크 오류는 5초·15초·60초 뒤 다시 시도하고, 새 편집이 있으면 그때도 시도한다. 권한·삭제·읽을 수 없는 파일은 사용자가 다시 시도할 때까지 멈춘다. 상태 변화와 실패는 진단 로그에 남긴다.
9. **연결 바꾸기**: 저장은 한 번에 하나만 실행한다. 다른 파일을 열거나 만들거나 연결을 끊으면 세대를 올려 이전 파일 요청의 결과를 버린다. Drive 파일을 열 때는 먼저 연결을 바꾼 뒤 보드를 바꿔, 연 내용을 다시 쓰지 않는다. 처음에는 여는 것도 실행 취소할 수 있는 편집이었는데, 되돌리면 이전 보드가 방금 연 파일에 자동 저장되었다. 그래서 Drive에서 열기는 실행 취소 기록을 비우고 되돌릴 수 없게 한다. 그러면 Drive에 없던 이전 보드는 돌아갈 길이 없어지므로, 열기 전에 닫힌 보드로 따로 보관해 `최근 보드`에서 다시 열 수 있게 하고([ADR 0011](0011-board-per-tab.md)), 보관하지 못하면 열지 않는다. 연결을 바꾸기 직전에 한 번 더 저장해, 파일을 받는 동안의 편집도 이전 파일에 남긴다. 로컬 파일을 열 때도 새 보드처럼 밀린 편집을 먼저 저장한 뒤 동기화를 멈추고, 저장할 수 없으면 열지 않는다. 로컬 파일 열기와 새 보드는 연결을 끊은 뒤 바꾸므로 실행 취소해도 Drive 파일에 쓰지 않아, 실행 취소할 수 있는 편집으로 둔다. 사본 저장(`create`)은 새 파일이 생길 때까지 원래 연결과 진행 중인 저장을 그대로 두므로, 실패해도 원래 파일과의 동기화가 이어진다. 접근이 끝나 `paused`가 된 뒤 끝난 저장은 기준 보드만 갱신하고 `paused`를 유지해, 다시 연결할 때 원격 변경을 먼저 합친다. 연결은 탭의 보드마다 따로 둔다([ADR 0011](0011-board-per-tab.md)). 처음에는 탭들이 한 연결을 공유하며 다른 탭의 변경을 따라갔지만, 탭마다 자기 보드를 갖게 되면서 없앴다.
10. **중복 없는 생성**: 새 파일은 `files.generateIds`로 미리 받은 ID로 만든다. 업로드 응답이 유실되거나(네트워크 오류·시간 초과·5xx) 409가 오면 그 ID의 파일을 읽는다. 이번 생성이 보낸 내용·이름이고 고른 폴더에 있으면 채택하고, 마지막으로 보낸 내용과 다르면 버전을 확인해 갱신한다. 다른 내용이면 덮어쓰지 않고 충돌로 멈춘다. 파일이 없으면 같은 ID로 다시 시도한다(3번, 0.5초부터 두 배씩 대기). 예약은 폴더별로 남아, 실패 뒤 같은 폴더에 다시 저장해도 같은 ID를 쓴다. 마지막 생성의 폴더·ID·시작 시각은 응답을 받을 때까지 localStorage에도 둔다(탭의 보드별). 연결된 파일 없이 연결되면(`DriveSync.recover`) 그 ID의 파일이 고른 폴더에 있는지 확인해 연결하고, 그 내용을 기준 보드로 삼아 그사이 편집을 저장한다. 이 탭에서 생성이 진행 중이면 찾지 않는다. 다른 파일을 열거나 동기화를 멈추면(새 보드, 로컬 파일 열기 포함) 기록과 이 페이지의 예약을 함께 지운다. 예약을 남기면 다른 보드의 다음 생성이 같은 ID로 이전 보드의 늦은 업로드를 찾아 자기 것으로 알고 덮어쓴다. 파일이 없으면 늦게 도착할 수 있는 업로드를 위해 10분 동안 기록을 남긴다.
11. **Drive가 기본 저장 위치**: 툴바 오른쪽에 테두리 있는 Drive 버튼을 늘 둔다. 연결 전에는 `Google Drive 연결`, 연결 후에는 `Drive에 저장`, 연결된 보드에서는 동기화 상태를 보여 준다. 처음 고른 저장 폴더는 탭이 함께 쓰도록 localStorage에 둔다(`stormlet.drive.folder`, 연결 해제 시 지움). 탭에서 빈 보드로 시작한 보드는 연결된 동안 첫 편집 때 그 폴더에 파일을 만든다. 예전부터 있던 보드나 동기화를 멈춘 보드는 자동으로 올리지 않는다. 연결된 보드에서 ⌘/Ctrl+S는 지금 저장이고, 아닐 때만 내려받기다. 제목 옆에는 보드가 어디에 있는지(`Google Drive에 자동 저장` / `이 브라우저에만 저장됨`) 표시한다.
12. **겹치는 이름에 번호**: 새 파일을 만들거나 보드 이름이 바뀌어 파일 이름을 바꿀 때, 그 폴더에서 Stormlet이 볼 수 있는 파일 이름을 읽어(`files.list`, 최대 10쪽) 겹치면 `이름 (n).stormlet` 중 비어 있는 첫 번호를 쓴다. 번호는 파일 이름에만 붙이고 보드 이름은 바꾸지 않는다. 이름이 `제목.stormlet`이나 `제목 (n).stormlet`이면 그대로 둔다. 이름은 어느 파일에 쓸지를 정하지 않으므로(파일은 ID로 구분), 목록을 읽지 못하면 번호 없이 진행한다.
13. **연결 해제는 잠시 멈춤, 계정 확인**: 연결 해제는 권한을 철회하지만 탭들의 파일 연결과 저장 폴더는 지우지 않고 `다시 연결` 상태로 둔다. 다시 연결하면 만료 뒤처럼 이어서 저장한다. 처음에는 연결 해제가 모든 연결을 지웠는데, 다시 연결해 저장하면 같은 보드가 새 파일로 갈라졌다. 지우기는 대화상자에서 따로 고른다(`disconnected` 메시지의 `forget`). 파일 연결과 폴더에는 계정 ID·이메일을 함께 둔다. 다시 이어서 저장하기 전에(`resume`, `saveNow`), 그리고 연결된 파일이 있는 동안 새 토큰이 올 때마다(연장, 다른 탭의 토큰; `reconnected`) 다음 저장 전에 연결된 계정을 확인해, 다른 계정이면 그 파일에 쓰지 않고 `account` 실패로 멈춘다. 계정을 알 수 없으면(요청 실패) 막지 않는다. 계정이 없는 예전 연결은 다음 재연결 때 계정을 기록한다. 다시 연결·연장할 때는 연결된 파일의 이메일을 `login_hint`로 넘겨 같은 계정을 고르게 한다. 권한 철회 뒤 `drive.file`로 예전 파일에 다시 접근되는지는 실제 계정으로 확인해야 하므로, 404·403이면 Picker로 같은 파일을 다시 골라 접근을 되살리는 `Drive에서 다시 찾기`를 둔다.
14. **보드 파일 형식**: Drive 파일은 `application/vnd.stormlet+json`으로 만들고, 열기 Picker는 `setMimeTypes`로 이 형식과 폴더만 보여 준다. 처음에는 `application/json`으로 저장해 Picker가 Drive의 모든 파일을 보여 줬다. Picker는 확장자로 거를 수 없고, 이름 검색(`setQuery`)으로 거르면 폴더를 둘러볼 수 없다. 예전 파일이 사라지지 않도록 `application/json`도 보여 주고, 저장할 때 형식이 다르면 메타데이터와 함께 올려 형식을 바꾼다. 내려받은 `.stormlet` 파일을 Drive에 직접 올리면 Drive는 형식을 모르는 파일(`application/octet-stream`)로 저장하므로 이 형식도 보여 준다. 그래서 Stormlet이 아닌 JSON·바이너리 파일도 섞여 보일 수 있다. Drive UI 연동(`연결 앱` 메뉴)을 하게 되면 이 형식을 기본 MIME 형식으로 등록한다.

## 결과

- 보드를 Drive에 두고 여러 기기에서 이어서 편집할 수 있다. 같은 파일을 다른 곳에서 고쳐도 다른 부분은 자동으로 합쳐진다.
- 실시간 공동 편집은 아니다. 실시간 협업은 ADR 0002의 계획대로 `BoardStore`의 Yjs 구현과 릴레이 서버로 따로 다룬다.
- 같은 origin의 다른 페이지도 채널에 참여해 토큰을 받을 수 있고, 브라우저 저장소도 origin 단위로 공유된다. GitHub Pages의 프로젝트 페이지는 모두 같은 origin이므로, Drive를 켜는 배포는 Stormlet 전용 origin을 쓴다([보안](../google-drive.md#보안)).
- 연결된 탭이 하나도 없으면 다시 로그인해야 하고, 연장 구간에 클릭이 없으면 만료된다.
- 실제 계정의 OAuth 동의, Picker, 권한 철회, ETag 노출은 모킹 테스트로 확인할 수 없어 배포 origin에서 검증해야 한다.
