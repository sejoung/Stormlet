# ADR 0008: 다국어 메시지 카탈로그

- 상태: 채택
- 날짜: 2026-11-08
- 선행: [로컬 우선 계층 구조](0001-layered-local-first.md)

## 배경

화면 문구가 한국어로 컴포넌트와 앱 훅 곳곳에 박혀 있었다. 오픈소스로 공개하면 한국어를 모르는 사용자도 쓰고, 다른 언어를 기여하기도 쉬워야 한다. 외부 라이브러리 없이도 필요한 기능(키 조회, 값 끼워 넣기, 언어 고르기)은 작다.

## 결정

1. **내부 키**: 코드는 문구 대신 `toolbar.undo` 같은 키를 쓴다. 키는 화면 영역별 이름공간으로 묶고, 값은 `{name}` 자리 표시자로 끼워 넣는다. 조각을 이어 붙이지 않고 문장 전체를 키 하나로 둬서 언어마다 어순이 달라도 된다.
2. **언어별 파일**: `src/i18n/locales/<언어>.ts` 하나가 한 언어다. `en.ts`가 키의 기준이고, 다른 언어 파일은 `Record<keyof typeof en, string>` 타입이라 키가 빠지면 타입 검사가 실패한다.
3. **영어 기본값**: 설정에서 고른 언어, 없으면 브라우저 선호 언어 중 카탈로그가 있는 첫 언어, 그것도 없으면 영어를 쓴다. 설정은 `자동(브라우저 언어)`과 각 언어를 고를 수 있고, 각 언어 이름은 그 언어로 표시해 어느 언어에서든 찾을 수 있다. 선택은 브라우저 저장소에 남는다.
4. **i18n 계층**: 카탈로그와 `translate`는 순수 TypeScript인 `src/i18n` 계층에 둔다. React 연결(`I18nProvider`, `useT`)은 components, 언어 감지와 저장은 adapters, 조립은 app이 맡는다.
5. **생성되는 데이터는 영어**: 보드 기본 제목(`My idea board`)과 새 프레임 제목(`Frame N`)은 화면 문구가 아니라 보드에 저장되는 데이터다. 언어 설정에 따라 바뀌면 같은 보드 안에서 제목이 섞이므로 모든 언어에서 영어로 만든다.
6. **규칙으로 강제**: 아키텍처 테스트가 카탈로그 밖의 문자열·JSX 텍스트에 라틴 문자가 아닌 글자가 있으면 실패시킨다. 카탈로그 테스트는 모든 언어의 키 집합과 자리 표시자가 영어와 같은지 검사한다.

## 결과

새 언어는 `locales/`에 파일 하나를 추가하고 `messages.ts`의 `LOCALES`와 카탈로그 목록에 등록하면 된다. 영어 문구가 코드에 남는 것은 규칙으로 잡지 못하므로 리뷰에서 본다. 단위 테스트는 기존 한국어 화면을 기준으로 작성되어 있어 한국어 브라우저로 실행하고, 언어 테스트만 그 설정을 바꾼다.
