# ADR 0011: 탭마다 자기 보드

- 상태: 채택
- 날짜: 2026-11-08
- 선행: [협업으로 옮길 수 있는 보드 모델](0002-collaboration-ready-model.md), [Google Drive 동기화](0010-google-drive-sync.md)
- 참고: Maplet ADR 0017(탭별 초안·작업 위치와 새 탭 새 맵)

## 배경

보드는 localStorage의 `stormlet.board` 한 칸에 있었다. 같은 브라우저의 탭은 모두 그 칸을 같이 썼다. 한 탭의 저장이 다른 탭의 변경을 덮지 않도록 탭끼리 `storage` 이벤트로 보드를 맞췄고, Drive 연결도 한 칸이라 다른 탭이 연 파일을 모든 탭이 따라갔다.

그래서 탭마다 다른 파일을 열어 둘 수 없었다. 새 보드나 다른 파일을 열면 지금 보드가 사라졌고, 이전 보드는 새로고침하면 사라지는 실행 취소 기록에만 남았다. 한 탭에서 편집한 직후 다른 탭이 파일을 바꾸면 그 편집을 잃는 틈도 있었다.

## 결정

1. **탭 하나에 보드 하나**: 보드는 슬롯 ID별로 저장한다. 보드는 `stormlet.board.<슬롯>`, 마지막 저장 시각은 `stormlet.saved.<슬롯>`에 둔다. Drive 연결과 기준 보드는 `stormlet.drive.file.<슬롯>`과 `stormlet.drive.base.<슬롯>`, 응답을 기다리는 생성은 `stormlet.drive.creating.<슬롯>`에 둔다. 손상된 보드는 `stormlet.board.<슬롯>.damaged`로 옮긴다. 다른 탭이 같은 칸을 쓰지 않으므로 탭끼리 보드나 연결을 맞추지 않는다. 그래서 ADR 0010의 연결 따라가기(`RemoteLinks.watch`)는 없앴다.
2. **탭이 보드를 정하는 순서**(`startTab`):
   1. 다른 탭이 주소로 요청한 보드: `#board=<슬롯>`이면 그 보드, `#new=<이름>`이면 새 보드다. 요청은 읽자마자 주소에서 지워 새로고침해도 되풀이하지 않는다.
   2. 새로고침이나 세션 복원이면 sessionStorage `stormlet.tab`에 기억한 자기 보드를 쓴다.
   3. 열린 Stormlet 탭이 하나도 없으면 가장 최근에 저장된 닫힌 보드를 이어서 연다. 앱을 다시 열면 하던 보드가 그대로 나온다.
   4. 그 밖에는 빈 새 보드로 시작한다.
3. **열린 탭 확인**: 탭은 열려 있는 동안 자기 슬롯의 Web Lock(`stormlet:board:<슬롯>`)을 잡는다. 새로고침 중에는 닫히는 페이지가 잠금을 잠깐 더 쥐고 있을 수 있어 1초까지 기다린다. 그래도 잠금을 얻지 못하면 sessionStorage가 복사된 탭 복제로 보고 새 보드로 시작한다. 다른 탭이 연 보드는 이어받거나 지우지 않는다. Web Locks가 없는 브라우저는 모든 탭이 가장 최근 보드를 같이 쓰고, 예전처럼 `storage` 이벤트로 맞춘다.
4. **새 보드**: 지금 보드에 내용이 있으면 `#new=<이름>`을 붙여 새 탭을 연다(`noopener`, 이 탭의 sessionStorage를 넘기지 않음). 이름은 주소의 hash에만 있어 서버로 가지 않는다. 지금 보드가 비어 있으면 이 탭에서 바로 만든다.
5. **최근 보드**: `파일 → 최근 보드…`는 열린 탭이 없는 보드를 최근 저장순으로 보여 준다. 이름, 포스트잇 수, 저장 시각, 연결된 Drive 파일을 함께 표시한다. 지금 탭이 비어 있고 Drive에 연결되지 않았으면 그 탭에서 열고, 아니면 새 탭에서 연다. 삭제는 두 번 눌러야 하며, 지우는 동안 그 보드의 잠금을 잡아 다른 탭이 열지 못하게 한다.
6. **정리**: 내용도 Drive 연결도 없는 닫힌 보드는 탭이 시작할 때와 목록을 볼 때 지운다. 내용이 있는 보드는 사용자가 지울 때까지 남는다.
7. **이전**: 예전의 `stormlet.board`와 Drive 키는 처음 시작할 때 새 슬롯 하나로 옮긴다. 원본 데이터를 그대로 옮기므로 손상된 보드도 그대로 잡힌다. 사본을 모두 쓴 뒤에만 원본을 지우고, 쓰기가 실패하면 원본을 남긴다. 여러 탭이 동시에 이전하지 않도록 `stormlet:migrate` 잠금 안에서 한다.

## 결과

- 탭마다 다른 보드와 다른 Drive 파일을 열어 둘 수 있다. 새 보드와 다른 보드 열기가 지금 보드를 지우지 않는다.
- 같은 Drive 파일을 두 탭에서 열면 각자 저장하며, 버전 확인과 3방향 병합으로 합쳐진다. 다른 탭의 편집은 화면에 바로 보이지 않고 저장할 때 합쳐진다.
- 액세스 토큰은 지금처럼 탭 사이에 넘겨준다(ADR 0010). 한 탭에서 연결을 해제하면 모든 탭의 동기화가 멈춘다.
- 닫은 탭의 보드는 브라우저 저장소에 쌓인다. 저장 공간은 origin당 약 5MB이고 같은 origin의 다른 앱과 나눠 쓴다. 브라우저는 저장소를 지울 수 있으므로(사이트 데이터 삭제, Safari의 7일 미사용 정리), 오래 보관할 보드는 Drive나 파일에 둔다.
- 시작할 때 잠금을 확인하느라 화면이 잠깐 늦게 뜰 수 있다. 새로고침에서는 최대 1초다.
- `noopener`로 연 창은 결과를 돌려주지 않아 팝업이 차단됐는지 알 수 없다. 클릭 처리 안에서 열기 때문에 보통은 차단되지 않는다.

## 검증

- 단위 테스트: 이전, 새로고침과 탭 복제, 최근 보드 이어 열기와 빈 보드 정리, `#new`·`#board` 요청, Web Locks가 없을 때, 목록·열기·삭제, 슬롯별 Drive 연결과 생성 기록, 새 보드와 최근 보드 화면.
- 브라우저 테스트: 새 보드가 새 탭에서 열리고 지금 보드는 남음, 새 탭의 새로고침, 닫은 탭의 보드를 최근 보드에서 열기, 모든 탭을 닫고 다시 열면 최근 보드로 시작, 두 탭이 각자 다른 Drive 파일에 저장, 새 탭이 토큰을 이어받음.
